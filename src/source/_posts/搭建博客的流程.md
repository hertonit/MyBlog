## 配置环境

该博客使用静态站点生成器 [Hexo](https://hexo.io/zh-cn/docs/) 和主题 [Butterfly](https://butterfly.js.org/posts/21cfbf15/) 构建，操作系统使用 Ubuntu。点击链接可进入官方文档。

{% note warning %}
**注意：在 Ubuntu 环境中初始化 Hexo 时，建议单独创建一个空文件夹。**
{% endnote %}

## 自定义主题

自定义主题可以使用 [Butterfly](https://butterfly.js.org/posts/21cfbf15/)。如果要覆盖主题配置，可以在 Hexo 根目录创建 `_config.butterfly.yml` 配置文件，在其中引入自定义 CSS 和 JS 文件。文件分别放在 `source/css/custom.css` 和 `source/js/custom.js` 中，配置如下：

```yaml
inject:
  head:
    - '<link rel="stylesheet" href="/css/custom.css">'
  bottom:
    - '<script src="/js/custom.js"></script>'
```

在自定义主题的过程中，CSS 样式可能没有生效，原因可能是文件未加载、浏览器缓存、选择器未匹配或样式优先级问题。可以检查原因，再按需调整选择器，也可以借助 AI 辅助调试。

## 部署网站

首先需要注册一个阿里云账号，购买一台云服务器，这里服务器的操作系统使用 Ubuntu。

### 连接服务器

生成 SSH 密钥并连接服务器。执行第一行命令会生成两个文件，后缀为 `.pub` 的是公钥，另一个是私钥。在阿里云控制台中选择服务器所在地域，找到密钥对管理，导入生成的公钥，并按照控制台指引绑定到实例，然后使用私钥连接服务器。

![](/img/搭建博客的流程1.png)

```shell
ssh-keygen -t ed25519 -f ./ecs_key
ssh -i ./ecs_key 用户名@服务器IP
```

### 将静态网站文件上传至服务器

{% note info %}
PATH1 是生成的 public 目录中的内容路径，PATH2 是服务器已配置的网站根目录路径。上传静态文件后，由服务器上的 Nginx 等 Web 服务器提供访问。
{% endnote %}

```shell
hexo clean
hexo g
scp -i ./ecs_key -r PATH1 用户名@服务器IP:PATH2
```

## GitHub Actions

由于每次修改完博客，都要执行一系列命令，包括反复切换文件路径、连接服务器和上传文件，十分繁琐，于是我向 GPT 大人求助，让它给出了一套自动部署方案。

### SSH 客户端配置

为了更方便地连接服务器和操作 GitHub 仓库，编辑本机的 `~/.ssh/config` 文件，添加如下配置：

```sshconfig
# 通过 SSH 连接 GitHub 远程仓库
Host github.com
    HostName github.com
    User git
    IdentityFile GitHub登录私钥路径
    IdentitiesOnly yes

# 通过 SSH 连接服务器
# 服务器连接别名
Host blog-server
    # 服务器公网 IP
    HostName 服务器IP
    # 登录用户名
    User root
    # SSH 服务端口
    Port 22
    # 本地私钥路径
    IdentityFile 服务器登录私钥路径
    # 仅使用配置指定的身份密钥
    IdentitiesOnly yes
```

使用以下命令可在连接 Github 远程仓库的时候不需要密码, 测试 GitHub 的 SSH 认证，并连接服务器：

```shell
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/密钥文件名

ssh -T git@github.com
ssh blog-server
```

### 将源代码上传至 GitHub 仓库

```shell
git init
git add .
git commit -m "类型: 描述"
git branch -M main
git remote add origin git@github.com:用户名/仓库名.git
git push -u origin main
```

### 配置仓库机密

在 GitHub 仓库的 `Settings → Secrets and variables → Actions → New repository secret` 中设置如下仓库机密：

| Secret 名称 | 含义 |
| --- | --- |
| `SSH_HOST` | 服务器 IP 地址 |
| `SSH_HOST_KEY` | 服务器的 SSH 主机公钥，用于校验服务器身份，不是登录密钥的公钥 |
| `SSH_PORT` | SSH 服务端口，默认 22 |
| `SSH_PRIVATE_KEY` | 登录服务器所用的完整私钥，包含首尾标记；以下工作流使用未设置保护口令的私钥 |

![](/img/img4.png)

在服务器登录用户的 `~/.ssh/authorized_keys` 中写入与 `SSH_PRIVATE_KEY` 对应的登录公钥，使用 `>>` 追加重定向写入。下方工作流使用 root 用户，对应路径是 `/root/.ssh/authorized_keys`。这里写入的不是 `SSH_HOST_KEY`。这个操作与在阿里云控制台中配置登录公钥的作用类似，但手动添加的公钥不会自动出现在阿里云控制台的密钥对列表中。

### 编写工作流配置文件

将以下内容保存到仓库根目录的 `.github/workflows/deploy.yml`。该配置假设 Hexo 项目位于仓库的 `src` 目录中，`package-lock.json` 已提交，`package.json` 已配置 `clean` 和 `build` 脚本，分别执行 `hexo clean` 和 `hexo generate`。服务器需已安装 rsync，允许 root 用户通过公钥登录，并已将 `/www/blog/public` 配置为网站根目录。

```yaml
# 工作流名称
name: Deploy blog

on:
  # 推送到 main 分支时自动执行
  push:
    branches: [main]
  # 允许在 GitHub Actions 页面手动执行
  workflow_dispatch:

# 允许工作流读取仓库内容
permissions:
  contents: read

concurrency:
  # 同组部署任务不能同时执行
  group: deploy-blog
  # 新任务触发时，不取消正在执行的任务
  cancel-in-progress: false

jobs:
  deploy:
    # 使用 GitHub 提供的 Ubuntu 运行环境
    runs-on: ubuntu-latest
    steps:
      # 拉取仓库代码
      - uses: actions/checkout@v4

      # 配置 Node.js，并缓存 npm 下载的数据
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm
          # 根据锁文件生成缓存标识
          cache-dependency-path: src/package-lock.json

      - name: Build Hexo
        # 在仓库的 src 目录中执行构建命令
        working-directory: src
        run: |
          # 按照 package-lock.json 安装依赖
          npm ci

          # 执行 package.json 中的 clean 脚本
          npm run clean

          # 执行 package.json 中的 build 脚本
          npm run build

          # 检查生成的首页是否存在且非空，失败则停止
          test -s public/index.html

      - name: Upload website
        env:
          # 服务器 IP 地址
          SSH_HOST: ${{ secrets.SSH_HOST }}
          # SSH 服务端口
          SSH_PORT: ${{ secrets.SSH_PORT }}
          # 登录私钥，与服务器 authorized_keys 中的登录公钥配对
          SSH_PRIVATE_KEY: ${{ secrets.SSH_PRIVATE_KEY }}
          # 服务器主机公钥，用于验证服务器身份
          # 来自服务器的 /etc/ssh/ssh_host_ed25519_key.pub
          SSH_HOST_KEY: ${{ secrets.SSH_HOST_KEY }}
        run: |
          # 命令失败、使用未定义变量或管道中命令失败时退出
          set -euo pipefail

          # 检查必需的仓库机密是否已设置
          : "${SSH_HOST:?Set SSH_HOST secret}"
          : "${SSH_PRIVATE_KEY:?Set SSH_PRIVATE_KEY secret}"
          : "${SSH_HOST_KEY:?Set SSH_HOST_KEY secret}"

          # 未设置端口时，默认使用 22
          SSH_PORT="${SSH_PORT:-22}"

          # 在 GitHub 运行机器上创建 SSH 目录，仅当前用户可访问
          install -d -m 700 ~/.ssh

          # 将登录私钥写入 GitHub 运行机器上的临时文件
          printf '%s\n' "$SSH_PRIVATE_KEY" > ~/.ssh/blog_deploy

          # 私钥仅允许当前用户读写
          chmod 600 ~/.ssh/blog_deploy

          # 保存可信服务器的主机公钥，用于核对服务器身份
          # 第一行用于默认端口的主机匹配
          printf '%s %s\n' "$SSH_HOST" "$SSH_HOST_KEY" > ~/.ssh/known_hosts

          # 第二行提供带端口的主机匹配格式
          printf '[%s]:%s %s\n' "$SSH_HOST" "$SSH_PORT" "$SSH_HOST_KEY" >> ~/.ssh/known_hosts

          # 将 src/public/ 中的内容同步到服务器的网站目录
          # -a：归档模式；-z：传输时压缩
          # --omit-dir-times：不保留目录修改时间
          # --no-perms：不保留源文件权限
          # --no-owner、--no-group：不保留源文件所有者和所属组
          # -i：指定登录私钥；-p：指定 SSH 端口
          # BatchMode=yes：禁止交互式密码和口令提示
          # IdentitiesOnly=yes：仅使用配置指定的身份密钥
          # StrictHostKeyChecking=yes：严格校验服务器主机密钥
          # 未使用 --delete，因此不会删除服务器上多余的旧文件
          rsync -az --omit-dir-times --no-perms --no-owner --no-group \
            -e "ssh -i $HOME/.ssh/blog_deploy -p $SSH_PORT -o BatchMode=yes -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes" \
            src/public/ "root@$SSH_HOST:/www/blog/public/"
```

### 编写脚本文件
现在已经完成了自动部署，但本地每次改完还要执行一系列提交暂存区，工作区相关的 git 命令，为了方便可以写一个简单的 `run.sh`脚本和 `commit_text.txt` 文件在 hexo 的根目录里，以后只需要把提交描述写在 `commit_text.txt` 里，然后执行 `./run.sh` 就可以不需要写前置的命令了，`.gitignore` 里要忽略这两个文件。

```shell
msg=$(cat ~/project/blog/src/commit_text.txt)
hexo g
git add .
git commit -m  ${msg}
git push origin main
```
