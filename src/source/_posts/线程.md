## 线程与进程
> **进程：**操作系统进行资源分配的基本单位，是程序的一次执行实例，拥有独立的虚拟地址空间、文件描述符等系统资源，进程之间相互隔离。
> **线程：**操作系统 CPU 调度的基本单位，隶属于进程；一个进程内可以包含多个线程，同进程的线程共享进程的地址空间与大部分资源，每个线程私有独立的调用栈、寄存器上下文。

进程就是一个程序实例，启动程序的时候操作系统会创建一个进程分配给这个程序，进程创建后，还会创建一个主线程，线程必须依附于进程存在。

## 线程池
线程池是一种管理和复用线程的机制。它通常会预先创建一组线程，并把任务放入任务队列中。多个线程并发执行时，任务实际开始和完成的顺序不一定与提交顺序一致。空闲线程从队列中取出任务执行，完成后继续处理其他任务，而不是每次都创建和销毁线程，减少线程创建和销毁的开销。

## C++多线程

### 创建线程
#### `thread`
C++11 引入了新的标准线程库 `std::thread`。`std::thread` 在 `<thread>` 头文件中声明，因此使用 `std::thread` 时需要包含 `<thread>` 头文件，创建线程 `std::thread t1(函数, 参数)`。

```c++
#include<iostream>
#include<thread>
#include<unistd.h>

void print(int x){
    for(int i = 1;i <= x; i++){
        std::cout << i << "\n";     
    }
    //sleep(1000);
}

struct Printer{
    void operator()(int x) const{
        print(x);
    }
};

int main(){
    std::thread t1(print, 4); //函数指针的方式创建线程
    //std::thread t1(Printer{}, 4); //函数对象的方式创建线程
    //std::thread t1([](int x){函数体}, 4); //lambda函数的方式创建线程
    t1.join();//等待线程完成
    //sleep(1000);
    return 0;
}
```
此时 `对象t1 ── 管理 ──> 执行 print() 的线程` 。
通过 `std::thread t1(函数, 参数)` 创建了一个线程，执行 `print` 函数，输出结果：
```text
1
2
3
4
```

### 线程管理
#### `join()`
`std::thread` 的析构函数有一条规则，如果对象析构时仍然关联着线程，就调用 `std::terminate()`。

`join()` 用于等待线程完成执行，还会解除线程与对象的关联。对于已经创建线程的 `std::thread` 对象，如果既不调用 `join()` 也不调用 `detach()` 就直接销毁该对象，会触发 `std::terminate()`，终止程序，即使对应线程已经执行结束也是如此。`t1.join()` 会阻塞主线程执行后面的代码，等 `t1` 线程完成才会放行。如果我们将线程传入的参数修改成 10 ，并且注释 `t1.join()`，一次运行的输出结果如下，具体输出和顺序可能不同：
```text
terminate called without an active exception
1
2
3
Aborted                    ./main.exe
```
在本例中，主线程跑完 `main()`，局部对象 `t1` 被析构，但此前没有调用 `join()` 或 `detach()`，因此触发 `std::terminate()`，输出了这个报错。原因是 `t1` 对象的析构。

接下来我们恢复 `t1.join()`，取消 `print()` 中 `sleep(1000)` 的注释。这里使用 Linux 环境，`sleep(1000)` 表示休眠 1000 秒。


#### `detach()`
`detach()` 将线程与管理线程的对象分离，分离之后不能使用对象管理该线程。

### 线程的传参
`std::thread` 默认会复制或移动参数到内部存储中，使用 `std::ref()` 可以让线程函数通过引用访问原来的变量，也可以使用指针或引用捕获的 lambda。需要保证原变量在线程访问期间仍然有效。

### 线程的互斥与共享
#### 互斥量
用于防止多个线程同时访问共享资源。当一个线程需要访问共享资源时，它首先需要锁定（lock）互斥量。如果互斥量已经被其他线程锁定，那么请求锁定的线程将被阻塞，直到互斥量被解锁（unlock）。`std::mutex` 就可以用来保护共享资源，防止数据竞争。

#### `mutex`
```c++
#include<iostream>
#include<thread>
#include<mutex>

std::mutex mtx;
void print(int x){
    mtx.lock();//锁定互斥锁
    std::cout << x << "\n";
    mtx.unlock();//释放互斥锁
}

int main(){
    std::thread t1(print, 1); //函数指针的方式创建线程
    std::thread t2(print, 2); //函数指针的方式创建线程
    std::thread t3(print, 3);
    t1.join(),t2.join(),t3.join();
    return 0;
}
```
```text
1
2
3
```
上面只是一次可能的输出，三个线程的输出顺序不固定。

将 `mtx.unlock()` 注释掉，一次运行中观察到的输出为

#### `std::lock_guard`
当离开作用域的时候，`std::lock_guard` 的析构函数会调用所管理互斥量的 `unlock()`，自动释放锁，但它不能中途自己释放互斥锁。
```c++
std::mutex mtx;
void print(int x){
    std::lock_guard<std::mutex> lk(mtx);
    std::cout << x << "\n";
}
```
#### `std::unique_lock`
定义方式和性质同上，区别在于 `std::unique_lock` 更加灵活。

| 能力 | `lock_guard` | `unique_lock` |
|---|---|---|
| 直接传入互斥量构造时加锁、析构时若持锁则解锁 | 支持 | 支持 |
| 中途解锁、重新加锁 | 不支持 | 支持 |
| 延迟加锁、尝试加锁 | 不支持 | 支持 |
| 查询是否持有锁 | 不支持 | 支持 |
| 转移锁的管理权 | 不支持 | 支持移动 |
| 配合 `std::condition_variable` | 不支持 | 支持 |
#### `std::condition_variable`
```c++
#include<iostream>
#include<thread>
#include<condition_variable>
#include<mutex>
#include<functional>

std::mutex mtx;
std::condition_variable cv; 

void print(int &x){
    {
        std::lock_guard<std::mutex> lk(mtx);
        for(int i = 1; i <= 10; i++) x += i;
    }//释放锁
    cv.notify_one(); // 通知主线程重新检查条件
}

int main(){
    int num = 0;
    std::thread t1(print, std::ref(num)); //函数指针的方式创建线程
    {
        std::unique_lock<std::mutex> uk(mtx);
        cv.wait(uk,[&](){
            return num >= 10;
        });
        std::cout << num << "\n";
    }
    t1.join();
    return 0;
}
```
```text
55
```
`wait(lock, 条件)` 会在持有锁时检查条件：条件不满足，就原子地释放锁并进入等待；收到 `notify_one()`、`notify_all()` 的通知或发生虚假唤醒后，重新获得锁并检查条件。条件仍不满足则继续等待，满足则返回，且仍然持有锁。

原子操作是指：在多个线程看来，一个操作不可分割，不会暴露只完成了一部分的中间状态。这里的原子操作，指 `wait()` 中的：释放互斥锁，并进入等待状态。这两件事作为一个不可分割的整体完成，避免在它们之间错过通知。
