## 线程池
线程池是一种管理和复用线程的机制。它通常会预先创建一组线程，并把任务放入任务队列中。多个线程并发执行时，任务实际开始和完成的顺序不一定与提交顺序一致。空闲线程从队列中取出任务执行，完成后继续处理其他任务，而不是每次都创建和销毁线程，减少线程创建和销毁的开销。

## C++模板
>C++ 模板就是：把类型也当作参数，让同一份代码能用于不同的数据类型。

### 函数模板
```c++
// //单参数模板
template<typename T>
void count(T x){...}

// //多参数模板
template<typename T, typename U>
void count(T x, U y){...}

//函数返回值是模板参数
// R 无法从函数实参推导，count<int>(3,4)
//结构体和类模板必须要指定类型
template<typename R,typename T,typename U>
R count(T x, U y){...}

//不定长参数模板，参数数量大于0
template<typename U,typename... Args>
auto count(U x, Args...args){...}
```
这里 typename... Args 声明一包类型，Args... args 声明对应的一包函数参数。使用 args... 可以把它们展开到函数实参列表等位置；例如 make_tuple(x, args...) 就是把所有参数放进元组。

### 结构体与类模板
```c++
//结构体模板
//调用：Point<int>p
template<typename T>
struct Point{
    T x,y;
};

//类模板
//调用：Point<int>p
template<typename T>
class Point{
public:
    T x,y;
};
```

## future

### future的作用

普通函数调用时，调用方会等函数执行完，直接接收返回值：

```cpp
int add(int a, int b) {
    return a + b;
}

int answer = add(2, 3); 
```

线程池不一样，你把任务交给它后，任务可能还在排队，也可能正在其他线程中执行。此时 `submit` 可以先返回，让你继续做其他事情。

那结果以后从哪里拿？用 `std::future`。可以把它理解成一张“取结果的凭证”：现在先拿凭证，等需要结果时再取。

```cpp
ThreadPool pool(2);

std::future<int> result = pool.submit(add, 2, 3);

// 可以先做其他事情，任务可能仍在排队或执行

int answer = result.get(); // 没完成就等待，完成后得到 5
```

`future<int>` 的意思是“以后能从这里取出一个 int”，不是说它现在就是一个 int。`future` 本身也不会创建线程或执行任务，真正干活的是线程池中的工作线程。

### get、wait 和 wait_for

| 操作 | 含义 |
| --- | --- |
| `result.get()` | 等待完成并取出结果；如果任务抛出异常，就在这里重新抛出 |
| `result.wait()` | 只等待完成，不取结果，之后仍可以调用 `get()` |
| `result.wait_for(时间)` | 最多等指定时长，检查结果是否准备好 |

```cpp
if (result.wait_for(std::chrono::milliseconds(100))
    == std::future_status::ready) {
    std::cout << result.get() << '\n';
} else {
    std::cout << "任务还没完成\n";
}
```

这段接在 `submit` 后使用，不要先调用前面示例中的 `get()`。对于这里线程池返回的 future，等待超时只表示还没拿到结果，不会取消任务。

普通 `future` 的 `get()` 只能取一次，取完就不能再对它调用 `get()` 或等待。它也不能直接复制，但可以用 `std::move` 转交给另一个变量。如果确实需要多个地方反复读取同一个结果，可以进一步学习 `shared_future`。

### 异常

没有返回值的任务对应 `future<void>`：

```cpp
auto result = pool.submit([] {
    std::cout << "任务完成\n";
});

result.get(); // 没有数值可取，但仍会等待完成、检查异常
```

任务通过下面的 `packaged_task` 执行时，如果任务函数抛出异常，异常会被保存起来，调用 `get()` 时再交给调用方：

```cpp
auto result = pool.submit([]() -> int {
    throw std::runtime_error("计算失败");
});

try {
    int answer = result.get();
    std::cout << answer << '\n';
} catch (const std::exception& e) {
    std::cout << e.what() << '\n';
}
```

### packaged_task

`future` 负责取结果，`packaged_task` 负责包装一个任务，并在任务执行后保存返回值或异常。它们共享同一份结果存储。

下面这个例子不需要线程池，先看清它们如何配合：

```cpp
#include <future>
#include <iostream>

int main() {
    std::packaged_task<int()> task([] {
        return 2 + 3;
    });

    std::future<int> result = task.get_future();
    task(); // 到这里才真正执行函数，结果被保存起来
    std::cout << result.get() << '\n'; // 5
}
```

`int()` 表示“一个不接收参数、返回 int 的函数形式”。不要把它当成在这里调用某个函数。

对照后面的线程池：

```cpp
auto task = std::make_shared<std::packaged_task<R()>>(
    std::bind(std::forward<F>(f), std::forward<Args>(args)...));

auto result = task->get_future();

tasks.emplace([task] {
    (*task)();
});

return result;
```

按职责来理解：

1. `bind` 把函数和参数绑在一起。例如把 `add`、`2`、`3` 绑成一个“调用时直接算 2 + 3”的任务，所以后面不需要再传参数。
2. `packaged_task<R()>` 包住这个任务，负责保存它执行后的结果或异常。
3. `get_future()` 取出对应的结果凭证，同一个 packaged_task 只能这样取一次。
4. 把 `[task] { (*task)(); }` 放入队列，稍后由工作线程调用。`task` 是智能指针，所以 `(*task)()` 才是在调用里面的任务。
5. `submit` 把 `result` 返回给调用方。任务完成和 `submit` 返回的先后顺序不固定，但调用方都可以通过 `get()` 正确等待结果。

这里用 `shared_ptr`，一方面让任务在排队期间继续存在；另一方面，这个队列使用 `std::function<void()>`，要求放进去的函数对象能够复制，而 `packaged_task` 本身不能复制，捕获一个可复制的智能指针就能满足要求。

你可以记住这条关系：

```text
调用方：submit 得到 future → 继续做事 → get 取结果
工作线程：从队列取任务 → 执行 packaged_task → 保存结果
```

## decltype

`decltype(表达式)` 得到一个类型，可以用在声明变量、定义类型别名、写函数返回类型的地方。

```cpp
int a = 2;
double b = 3.5;

decltype(a) x = 10;       // x 是 int
decltype(a + b) y = 1.5; // a + b 的类型是 double，所以 y 是 double

using Number = decltype(a + b);
Number z = 4.5;          // 等价于 double z = 4.5;
```

注意：`decltype` 要的是类型，不是表达式算出来的值。

```cpp
int add(int a, int b) {
    return a + b;
}

using R = decltype(add(2, 3)); // R 是 int，这里并没有执行 add
R answer = add(2, 3);         // 这里才真正调用 add，得到 5
```

编译器只需要判断“如果这样调用，返回的是什么类型”。表达式虽然不执行，但仍然要写得合法。

### auto 和 decltype 的区别

```cpp
auto a = 10;        // 根据右边的初始化表达式，推导 a 的类型
decltype(a) b = 20; // 查询 a 的类型，再用这个类型声明 b
```

`auto` 适合“我现在要定义变量，让编译器替我填类型”；`decltype` 适合“我想拿到某个表达式的类型，放到其他位置使用”。

普通 `auto` 通常会去掉引用和最外层的 const，而 `decltype` 可以保留这些信息：

```cpp
int n = 10;
int& ref = n;

auto a = ref;          // int，复制一个值
decltype(ref) b = n;   // int&，仍然是引用
```

### 在线程池里的作用

线程池能接收不同任务：

```cpp
auto a = pool.submit([] { return 10; });    // future<int>
auto b = pool.submit([] { return 3.14; });  // future<double>
auto c = pool.submit([] { /* 做事 */ });   // future<void>
```

所以 `submit` 不能把返回类型写死成 `future<int>`。它需要先知道任务函数返回什么，再返回对应的 `future<那个类型>`。

先用一个简单函数理解 `decltype` 如何帮忙：

```cpp
template <typename F, typename... Args>
auto call(F f, Args... args) -> decltype(f(args...)) {
    return f(args...);
}
```

后面的 `-> decltype(f(args...))` 是返回类型。这里把返回类型写在参数列表后面，是为了能直接使用刚声明的 `f` 和 `args`。

调用 `call(add, 2, 3)` 时，可以这样理解：

```text
decltype(f(args...))
          ↓
判断 add(2, 3) 的返回类型
          ↓
得到 int，所以 call 的返回类型是 int
```

类型判断不会执行函数；真正执行的是函数体中的 `return f(args...);`。

对应到线程池的接口，可以用下面的简化形式理解：

```cpp
template <typename F, typename... Args>
auto submit(F f, Args... args)
    -> std::future<decltype(f(args...))>;
```

这只是帮助理解返回类型的接口示意，省略了函数实现，也没有完整处理实际版本中的参数转交方式。

### invoke_result_t

你下面的线程池实际上使用的是：

```cpp
using R = std::invoke_result_t<F, Args...>;
```

可以直接读成：“用 Args... 这些类型的参数调用 F，返回类型是什么？把它叫作 R。”它从类型判断调用结果，支持普通函数、函数对象和成员函数指针等调用形式。

它和 `decltype(f(args...))` 都能用于判断调用的返回类型，但支持的调用形式、参数的传递方式需要对应，不能在所有代码里直接互换。当前实现保留 `invoke_result_t` 即可，不需要为了学习 `decltype` 把它替换掉。

得到 R 后，后面几行就容易看懂了：

```cpp
std::future<R>                // 调用方以后取出一个 R 类型的结果
std::packaged_task<R()>       // 包装一个不接收参数、返回 R 的任务
```

如果任务返回 int，这两个地方分别就是 `future<int>` 和 `packaged_task<int()>`；如果任务不返回值，就是 `future<void>` 和 `packaged_task<void()>`。

### 括号的影响

对于直接写出的变量名，`decltype` 取得变量声明时的类型：

```cpp
int n = 10;
decltype(n) a = n;   // int
decltype((n)) b = n; // int&
```

`n` 是直接查询变量声明的类型；`(n)` 则按表达式判断，表示一个能指向原变量的表达式，所以这里得到引用类型。

```cpp
a = 20; // 改的是 a，不影响 n
b = 30; // b 引用 n，所以 n 也变成 30
```

因此不要为了“保险”随便给 decltype 里面的变量多套一层括号。当前先掌握 `decltype(变量名)` 和 `decltype(函数调用)`，就足够读懂线程池中的返回类型问题。


## 简易线程池
该线程池由任务队列和任务线程组成，先创建多个线程，由 condition_variable 来控制线程，初始线程全部睡眠，有任务提交再随机唤醒一个线程来完成任务，如果要关闭线程池，需要先把任务都完成再切断对象和线程的联系，最后清空线程数组的对象。

`ThreadPool.hpp`
```c++
#pragma once

#include <condition_variable>
#include <cstddef>
#include <functional>
#include <future>
#include <memory>
#include <mutex>
#include <queue>
#include <stdexcept>
#include <thread>
#include <type_traits>
#include <utility>
#include <vector>

class ThreadPool {
public:
    explicit ThreadPool(
        std::size_t n = std::thread::hardware_concurrency());

    ~ThreadPool();

    ThreadPool(const ThreadPool&) = delete;
    ThreadPool& operator=(const ThreadPool&) = delete;

    // 模板必须留在头文件里，否则调用点实例化不出来
    template <typename F, typename... Args>
    std::future<std::invoke_result_t<F, Args...>>
    submit(F&& f, Args&&... args) {
        using R = std::invoke_result_t<F, Args...>;

        auto task = std::make_shared<std::packaged_task<R()>>(
            std::bind(
                std::forward<F>(f),
                std::forward<Args>(args)...));

        auto result = task->get_future();

        {
            std::unique_lock<std::mutex> lk(mtx);

            if (stop) {
                throw std::runtime_error(
                    "submit on stopped ThreadPool");
            }

            tasks.emplace([task] {
                (*task)();
            });
        }

        cv.notify_one();
        return result;
    }

    void shutdown();
    std::size_t count() const;

private:
    void work_loop();

    std::vector<std::thread> works;
    std::queue<std::function<void()>> tasks;

    std::mutex mtx;
    std::condition_variable cv;
    bool stop = false;
};
```

`ThreadPool.cpp`
```c++
#include "ThreadPool.hpp"

ThreadPool::ThreadPool(size_t n)
{
    n = std::max<size_t>(1, n);

    works.reserve(n);
    for (size_t i = 0; i < n; ++i)
    {
        works.emplace_back([this] { work_loop(); });
    }
}

ThreadPool::~ThreadPool()
{
    shutdown();
}

void ThreadPool::shutdown()
{
    {
        std::unique_lock<std::mutex> lk(mtx);
        if (stop)
            return;
        stop = true;
    }
    cv.notify_all();

    for (auto &f : works)
        if (f.joinable())
            f.join();

    works.clear();
}

size_t ThreadPool::count() const
{
    return works.size();
}

void ThreadPool::work_loop()
{
    for (;;)
    {
        std::function<void()> job;
        {
            std::unique_lock<std::mutex> lk(mtx);
            cv.wait(lk, [this] { return stop || !tasks.empty(); });
            if (stop && tasks.empty())
                return;
            job = std::move(tasks.front());
            tasks.pop();
        }
        job();
    }
}
```
